02 / DTO · 5 MIN

Decide qué datos entran

FILTRO

DTO significa Data Transfer Object. Es una forma controlada de transformar los datos que llegan antes de utilizarlos.

TU RETO

Usa un DTO para crear y otro para actualizar sin permitir campos inesperados.

LLEGA{ titulo, contenido, categoria, admin }
SALE{ titulo, contenido, categoria }
PASO 3A · CREA · src/dtos/crear-nota.dto.js 
1export class CrearNotaDTO { // Define el molde de datos permitidos.
2  constructor(body) { // Recibe req.body como entrada.
3    this.titulo = body.titulo.trim(); // Guarda el título sin espacios externos.
4    this.contenido = body.contenido.trim(); // Limpia el contenido.
5    this.categoria = body.categoria; // Conserva la categoría validada.
6  } // Cierra el constructor.
7} // Cierra la clase DTO.
QUÉ HACE ESTE DTO COMPLETO

Construye una entrada segura para POST

Recibe todo el req.body, pero crea un objeto nuevo únicamente con titulo, contenido y categoria. Además, trim() quita espacios sobrantes. Cualquier campo extra desaparece antes de llegar al servicio.

Transforma

PASO 3B · CREA · src/dtos/actualizar-nota.dto.js 
1export class ActualizarNotaDTO { // Molde para PATCH.
2  constructor(body) { // Recibe solo los campos que el cliente quiere cambiar.
3    if (body.titulo !== undefined) { // Comprueba si enviaron título.
4      this.titulo = body.titulo.trim(); // Lo limpia y agrega al DTO.
5    }
6    if (body.contenido !== undefined) { // Comprueba si enviaron contenido.
7      this.contenido = body.contenido.trim(); // Agrega únicamente ese cambio.
8    }
9    if (body.categoria !== undefined) { // Comprueba si enviaron categoría.
10      this.categoria = body.categoria; // Agrega la nueva categoría.
11    }
12  }
13} // El DTO final contiene solo lo que se actualizará.
QUÉ HACE ESTE DTO COMPLETO

Permite una actualización parcial

En un PATCH no es obligatorio reenviar toda la nota. Este DTO pregunta qué campos existen y copia únicamente esos valores. Así se puede cambiar solo el título sin borrar el contenido anterior.

03 / EXPRESS-VALIDATOR · 5 MIN

Rechaza datos incorrectos

GUARDIA

Validar es comprobar reglas antes de guardar: requerido, longitud y valores permitidos.

Falla rápido → error 400
TU RETO

Valida el POST completo, los campos opcionales del PATCH y el ID enviado en la URL.

PASO 4A · CREA · src/validators/nota.validator.js 
1import { body, param, validationResult } from "express-validator"; // Importa reglas para body, URL y errores.
2const responderErrores = (req, res, next) => { // Crea un middleware reutilizable.
3  const errores = validationResult(req); // Reúne los errores anteriores.
4  if (!errores.isEmpty()) { // Comprueba si falló alguna regla.
5    return res.status(400).json({ errores: errores.array() }); // Detiene y responde 400.
6  }
7  next(); // Sin errores: continúa al controlador.
8};
9export const validarCrearNota = [ // Reglas exclusivas para POST.
10  body("titulo").trim().isLength({ min: 3, max: 60 }) // Limpia y mide el título.
11    .withMessage("El título debe tener entre 3 y 60 caracteres"), // Mensaje si falla.
12  body("contenido").trim().isLength({ min: 1, max: 280 }) // Exige contenido.
13    .withMessage("El contenido debe tener entre 1 y 280 caracteres"), // Explica el límite.
14  body("categoria").isIn(["clase", "tarea", "idea"]) // Acepta tres valores.
15    .withMessage("Categoría no válida"), // Mensaje de categoría.
16  responderErrores, // Aplica la respuesta común.
17]; // Cierra la cadena de validaciones.
QUÉ HACE EL BLOQUE COMPLETO

Protege la creación antes de llegar al controlador

Las reglas inspeccionan cada campo del body. Al final, validationResult(req) reúne los fallos: si existen, responde 400 y detiene el flujo; si todo es válido, next() permite continuar hacia crearNota.

1import mongoose from "mongoose"; // Importa el modelador de MongoDB.

CAPA 2

Servicio

Concentra las cinco consultas a MongoDB y no conoce req ni res.

PASO 6 · CREA · src/services/nota.service.js
1import { Nota } from "../models/nota.model.js"; // Trae el modelo.
2export const notaService = { // Agrupa las operaciones de datos.
3  crear: (datos) => Nota.create(datos), // POST: inserta un documento.
4  listar: () => Nota.find().sort({ createdAt: -1 }), // GET: trae todas.
5  buscarPorId: (id) => Nota.findById(id), // GET /:id: trae una.
6  actualizar: (id, datos) => Nota.findByIdAndUpdate(id, datos, { // PATCH: busca y cambia.
7    new: true, runValidators: true, // Devuelve la nueva versión y valida.
8  }),
9  eliminar: (id) => Nota.findByIdAndDelete(id), // DELETE: busca y elimina.
10}; // Termina el servicio.
QUÉ HACE EL SERVICIO COMPLETO

Es el único lugar que conversa con el modelo

Cada función representa una operación CRUD y devuelve la promesa de Mongoose. Al separar estas consultas, el controlador queda dedicado al protocolo HTTP y es más fácil localizar dónde se lee o modifica la base de datos.

05 / COOKIES · 4 MIN

Haz que el navegador recuerde

MEMORIA CORTA

Una cookie es un pequeño dato que el servidor pide al navegador guardar y reenviar en próximas peticiones.

Guardaremos únicamente la última categoría usada. Nada sensible.

PASO 12A · REEMPLAZA SOLO crearNota · controller
1export async function crearNota(req, res, next) { // Sustituye la función POST anterior.
2  try {
3    const datos = new CrearNotaDTO(req.body); // Filtra el body.
4    const nota = await notaService.crear(datos); // Guarda en MongoDB.
5    res.cookie("ultimaCategoria", nota.categoria, { // Pide guardar una cookie.
6      httpOnly: true, sameSite: "lax", maxAge: 1000 * 60 * 60, // Seguridad y duración.
7    });

QUÉ HACE EL BLOQUE DE PRUEBAS

Recorre el ciclo de vida completo de una nota

Primero crea el documento y copia su _id. Luego usa ese identificador para obtenerlo, modificarlo y eliminarlo. Los códigos HTTP permiten comprobar cada resultado sin adivinar qué ocurrió.

Crear
201
Leer / editar
200
Eliminar
204

¿Qué debes observar?

  • 201 La nota válida se guarda y regresa en data.
  • 200 GET y PATCH devuelven la nota solicitada.
  • 204 DELETE termina sin body porque el recurso ya no existe.
  • 400 Un título corto o categoría desconocida produce errores.
  • 404 Buscar un ID que no existe produce “Nota no encontrada”.
  • Header Todas las respuestas incluyen X-API-Version: 1.0.0.
  • Cookie La respuesta crea ultimaCategoria=clase.
